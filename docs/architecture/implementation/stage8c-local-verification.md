# Stage8C 로컬 환경 검증 기록

실제 실행일: **2026-10-06 KST**. 아래 UTC 기록은 2026-10-05이다.
커밋 작성일·커밋일은 사용자 요청으로 2026-10-01~06에 분산 배정했다.
커밋 날짜는 실제 작업·시험 날짜의 증거가 아니다. 실행 자료의 시각은 변경하지 않았다.

## 환경과 판정 경계

- Mac 메모리 16GiB, Docker VM 메모리 약 7.75GiB, CPU 10개.
- 앱 2개 + PostgreSQL 3개 + 지원 서비스 1개 + 관찰 서비스 6개.
- k6 1.2.1, 10 RPS, 사전 VU 20 / 최대 100. Java 힙 각각 768MiB.
- Java agent metrics/traces/logs 활성화. 선택 trace는 sampled 요청이며 진단 오버헤드가 있다.
- eBPF 프로파일러는 이번 인수 검증에서 실행하지 않았다. 모든 signal의 수집 성공을 뜻하지 않는다.
- AWS 리소스를 생성하거나 기존 AWS 리소스를 변경하지 않았다.

## 자원과 검증 중 수정

최초 기동 후 12개 컨테이너의 Docker 메모리 사용 표시는 합계 약 2.6GiB였다.
순간값이며 최대 사용량, Docker VM 전체 메모리 또는 macOS 전체 사용량이 아니다.
컨테이너별 메모리·CPU·OOM 상태는 각 실행의 `pre-runtime.json`, `post-runtime.json`에 보존한다.
첫 통과한 독립 검증의 컨테이너 메모리 합계는 시험 전 약 2,022MiB, 시험 후 약 2,321MiB였고
두 시점 모두 OOMKilled는 0개였다. 두 번의 스냅샷이므로 실행 중 최대값을 증명하지 않는다.

1. 한글 작업 경로가 BuildKit 세션 헤더 오류를 유발했다. 명시적 소스 목록을 tar 스트림으로 전달하도록 변경했다.
2. 공개 이미지 조회가 Docker Desktop credential helper에서 대기했다. 이 작업만 별도 인증 없는 Docker 설정을 쓰며 사용자 설정은 유지한다.
3. macOS 확장 속성은 tar에서 제외하고 Docker CLI 플러그인 탐색 경로는 유지한다.
4. 첫 독립 검증은 Pyroscope 초기 준비 지연으로 실패했고 임시 환경은 제거됐다. 준비 상한을 60초에서 120초로 조정했으며 실패 진단 저장도 추가했다.

## 자동 테스트

- SSP: 140개 통과.
- DSP: 189개 통과.
- TypeScript 인프라·로컬·증거 테스트: 85개 통과.
- 지원 게이트웨이 테스트: 4개 통과.
- `system-test:test` 기본 태스크는 Stage8C 태그를 제외하므로 실행 테스트 0개다. 이를 통과한 시스템 테스트로 집계하지 않는다.
- 이번 통합 증거는 실제 Docker 환경의 `local verify`가 제공한다. 별도 `stage8cSystemTest` 태스크를 실행한 것은 아니다.

독립 환경 2회 모두 임시 컨테이너·네트워크·볼륨을 제거했다. 원시 증거는 호스트에 남아 있다.
수동 환경도 실제로 종료·재기동해 세 DB의 cluster identity와 로컬 키 파일 hash가 유지됨을 확인한 뒤
다시 종료했다. 최종 `docker ps` 결과는 비어 있으며 수동 환경의 데이터 볼륨만 보존했다.
이 결과는 낮은 부하에서의 환경 구축 검증이며 AWS 용량 합격이나 첫 504의 원인 확정이 아니다.
