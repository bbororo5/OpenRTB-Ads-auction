# DSP 입찰 실행권 입력 공간과 테스트 오라클

상태: 6단계 입찰 실행권 기준선

상위 문서: [DSP 상세 설계 로드맵](dsp-design-roadmap.md)

## 문제와 검증 목표

DSP는 인증된 SSP의 한 입찰 요청에 포함된 슬롯 경매들을 한 번만 조정한다. 같은 요청의 후속 호출은 최초 실행 결과를 기다리거나 다시 실행하지 않고 빠르게 거절한다. 최초 실행이 성공·실패·불확실 중 어느 결과로 끝나도 기억 수명 안에서는 새 실행권을 만들지 않는다.

검증할 핵심 성질은 다음과 같다.

1. 슬롯 경매는 `sspId + requestId + impressionId`로 식별한다.
2. 같은 `sspId + requestId`는 정규화된 요청 전체에 대해 같은 지문을 가져야 한다.
3. 같은 키에서 실행권을 얻는 호출은 최대 하나다.
4. 중복 호출은 최초 실행의 완료를 기다리지 않는다.
5. 최초 실행 실패는 같은 요청의 재실행 권한을 만들지 않는다.
6. 실행 마감과 중복 기억 수명은 서로 다른 시간 경계다.

## 입력 공간 분해

### 1. 경매 정체성

| 축 | 동치 분할 | 경계·대표 입력 |
|---|---|---|
| 인증 SSP | 같음 / 다름 | 같은 `requestId`라도 `ssp-1`, `ssp-2`는 별개 |
| 요청 ID | 같음 / 다름 | 같은 SSP 안에서만 중복 판정 |
| 슬롯 ID | 같음 / 다름 | 같은 요청의 `imp-1`, `imp-2`는 독립 경매 |
| 처리 위치 | 같음 / 다름 | 리전·인스턴스는 정체성에 포함하지 않음 |

오라클:

- 세 식별 필드가 모두 같을 때만 같은 슬롯 경매다.
- 빈 식별자는 계약 생성 단계에서 거부한다.
- 문자열 연결값이 아니라 구조화된 키의 값 동등성으로 판정한다.

### 2. 요청 내용 지문

| 축 | 동치 분할 | 기대 판정 |
|---|---|---|
| JSON·슬롯 표현 순서 | 슬롯 순서만 다름 | 같은 지문 |
| `tmax` | 같음 / 다름 | 다르면 다른 지문 |
| 슬롯 집합 | 같음 / 추가 / 제거 | 추가·제거는 다른 지문 |
| 슬롯 규격 | width 또는 height 변경 | 다른 지문 |
| 바닥가 | 같음 / 변경 | 다르면 다른 지문 |
| 노출 기한 | 같음 / 변경 | 다르면 다른 지문 |
| 요청 ID | 같음 / 다름 | 지문이 아니라 요청 키가 구분 |
| 수신 시각 | 같음 / 다름 | 지문에 포함하지 않음 |

오라클:

- 검증된 내부 메시지를 슬롯 ID 순으로 정규화한 결정적 바이트열에 SHA-256을 적용한다.
- 지문은 버전을 가지며 같은 버전·같은 의미 입력은 같은 32바이트 digest를 만든다.
- 같은 키·다른 지문은 `REQUEST_CONFLICT`이고 신규 실행으로 해석하지 않는다.

### 3. 실행권 상태

| 기존 상태 | 새 입력 | 오라클 |
|---|---|---|
| 없음 | 유효한 최초 요청 | 호출자 하나가 실행하고 `BidExecuted` |
| `IN_FLIGHT` | 같은 키·지문 | supplier를 실행하거나 기다리지 않고 `DUPLICATE_REQUEST` |
| `IN_FLIGHT` | 같은 키·다른 지문 | 즉시 `REQUEST_CONFLICT` |
| `TERMINAL` | 같은 키·지문 | 결과를 재사용하지 않고 `DUPLICATE_REQUEST` |
| `UNCERTAIN` | 같은 키·지문 | 재실행하지 않고 `DUPLICATE_REQUEST` |
| 기억 수명 만료 | 같은 키·지문 | 새 실행권을 획득할 수 있음 |

동시성 오라클:

- 같은 키·지문의 동시 호출 N개에서 supplier 호출 횟수는 정확히 1이다.
- 최초 supplier를 시험 장벽에서 멈춘 동안 후속 호출은 그 장벽 해제 전에 반환한다.
- 최초 실행의 예외 뒤 후속 호출의 supplier 호출 횟수는 0이다.

### 4. 시간과 기억 수명

| 축 | 동치 분할 | 오라클 |
|---|---|---|
| 실행 상태 | 진행 중 / 종결 | 진행 중 엔트리는 기억 수명이 지나도 교체하지 않음 |
| 기억 시각 | 직전 / 정확한 경계 / 직후 | 경계 이상에서 종결 엔트리 제거 가능 |
| 오래된 만료 표식 | 같은 엔트리 / 교체된 엔트리 | 교체된 엔트리는 제거하지 않음 |

실행 deadline은 입찰 조정의 유효성을 제한하고, 실행권 기억 수명은 같은 요청의 재실행을 막는다. 이 컴포넌트는 deadline을 새로 만들지 않으며 최초 명령에 포함된 deadline을 그대로 하위 조정자에게 전달한다.

### 5. 용량과 과부하

| 축 | 동치 분할 | 오라클 |
|---|---|---|
| 점유량 | 상한 미만 / 정확히 상한 | 상한에서는 새 키만 `CAPACITY_EXCEEDED` |
| 기존 키 | 상한 상태 | 기존 키의 중복·충돌 판정은 계속 가능 |
| 만료 엔트리 | 없음 / 있음 | 만료 정리 뒤 새 키 용량이 회복됨 |
| 동시 신규 키 | 상한 주변 경쟁 | 실제 엔트리 수가 상한을 넘지 않음 |

## 테스트 계층

1. 메시지 계약 시험은 슬롯 키의 namespace와 요청-슬롯 일치 조건을 검증한다.
2. 지문 단위 시험은 정규화 동치와 각 의미 필드의 민감도를 검증한다.
3. 실행권 단위 시험은 상태 전이와 반환 사유를 검증한다.
4. 장벽을 사용한 동시성 시험은 중복 호출이 대기하지 않는다는 시간적 오라클을 검증한다.
5. 가상 단조 시계 시험은 기억 수명 경계를 결정적으로 검증한다.
6. 전체 DSP 회귀 시험은 기존 예산·리스·통지 계약과의 비의도적 변경을 탐지한다.

시간 시험은 벽시계 지연이나 `sleep`에 의존하지 않는다. 장벽은 최초 실행의 진행 여부만 통제하고, 기억 수명은 주입한 단조 시계를 직접 이동한다.
