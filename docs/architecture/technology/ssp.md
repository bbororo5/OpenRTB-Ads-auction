# SSP 기술 기준선

상태: 첫 수직 흐름 구현 기준선 확정

근거: [제품 요구사항](../../requirements/product.md), [아키텍처 중요 요구사항](../../requirements/quality.md), [SSP 컨테이너](../views/ssp-containers.md)

## 1. 지금 확정하는 기술

| 경계 | 기준선 | 근거 |
|---|---|---|
| 실행 환경 | Java 21 | 제품 제약이자 현재 코드 기준선이다. |
| 공급자·렌더링 API | HTTP/JSON | 초기 외부 표현이며 성능 비교의 기준선이다. |
| DSP 연동 | HTTP/JSON, OpenRTB 2.6 하위 규격 | 세 DSP가 같은 경매·통지 의미를 사용한다. |
| 경매 멱등 상태 | 제한된 프로세스 메모리 | 5초의 요청 키·지문·최초 결과만 보존해 Hot Path 외부 조회를 피한다. |
| 렌더링 증표 | 버전형 이진 페이로드 + AEAD + Base64URL | 공급자·요청·슬롯·발급 리전 귀속과 낙찰 사실을 외부 키 조회 없이 2초 동안 검증한다. |
| 리전별 SSP 청구 기록 DB | PostgreSQL | ADR-007에서 성공 응답 전 내구 기록과 멱등 판정의 저장 기술로 승인했다. |
| 공급자 설정 | 서울 단일 쓰기 PostgreSQL + 도쿄 논리 복제 + 지역 메모리 스냅숏 | 설정 전파 지연을 허용해 경매 경로의 전역 조회와 합의를 제거한다. |
| 배포 전제 | 두 능동 리전, 리전별 다중 AZ | ADR-006의 장애 격리 경계다. |

이 기준은 SSP의 외부 계약과 데이터 권위를 고정한다.

## 2. 첫 구현에서 선택한 기술

| 경계 | 선택 | 적용 이유 |
|---|---|---|
| 공급자 HTTP 서버 | JDK `HttpServer` + 가상 스레드 | 작은 기준선으로 실행 모델을 측정하고 서버 제품 종속을 미룬다. |
| DSP 입찰·통지 | JDK `HttpClient` | 입찰은 DSP 회사별 클라이언트·연결과 동시 호출 상한을 분리하고, 통지는 별도 클라이언트를 사용한다. |
| JSON | Jackson 2.21 | 공급자 표현과 SSP가 소유한 OpenRTB 하위 규격을 내부 메시지와 분리한다. |
| 렌더링 증표 | JCA AES-GCM | 별도 암호 라이브러리 없이 기밀성·무결성을 제공한다. 활성 키와 이전 검증 키를 함께 주입해 짧은 유효 기간 중 키 교체를 허용한다. |
| 청구 저장 | JDBC + HikariCP + PostgreSQL | 슬롯 고유 키로 청구와 전달 작업을 한 행에 원자 추가한다. 시작 전 롤백 삽입으로 연결·스키마·쓰기 권한을 확인한다. |
| 전달 실행 | 단일 주기 실행기 | 한 실행당 한 작업만 임대해 실패 작업이 실행기를 독점하지 않는다. |

## 3. 측정 뒤 재검토할 기술

- HTTP 서버 제품과 실행 자원 격리
- DSP 입찰 하위 기한·연결 풀·동시 호출·응답 크기 상한
- PostgreSQL 연결 풀 크기와 전달 실행기 수
- 진입 계층의 Rendezvous Hash 구현 제품
- 경매·DSP 호출·렌더링·저장·통지를 잇는 관측 라이브러리

입찰 기준값은 하위 기한 35ms, DSP별 처리 중 호출 64개, 응답 64KiB다. 이는 대기열을 만들지 않는 안전한 시작값이며 기준선·용량·장애 시험으로 조정한다. 수치를 바꿔도 C2 경계와 데이터 권위는 바꾸지 않는다.
