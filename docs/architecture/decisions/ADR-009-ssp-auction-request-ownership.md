# ADR-009 분산 SSP의 경매 멱등성 방어

상태: 채택

근거: [요구사항](../../requirements/product.md), [부하 기준](../../requirements/workload.md), [ADR-004](ADR-004-auction-execution-path.md), [ADR-006](ADR-006-multi-region-service-topology.md)

## 배경

일반 부하 분산은 같은 요청을 같은 SSP 인스턴스로 보낸다는 보장이 없다. 반면 로컬 멱등성 상태는 해당 인스턴스 안에서만 보인다. 따라서 재시도가 다른 인스턴스에 도착하면 그 인스턴스는 기존 경매를 알 수 없고, 같은 광고 기회의 DSP 경매를 다시 시작할 수 있다. 최초 인스턴스가 DSP 호출 뒤 중단되면 이 판단 오류를 확인하거나 복구할 방법도 없다.

이 문제에서 외부 상태를 공유할지, 요청의 소유자를 안정적으로 고정할지를 비교했다.

## 결정

리전별 L7 진입 계층은 `providerId + providerRequestId`로 만든 경매 요청 키를 **Rendezvous Hash**로 라우팅한다. 소유 SSP는 5초 동안 로컬 상태로 중복을 방어한다. 요청별 외부 중복 저장소 조회는 사용하지 않는다.

## 선택지와 트레이드오프

| 후보 | 판단 |
|---|---|
| 외부 공유 중복 저장소 | 모든 SSP가 하나의 상태를 확인한다. 장애 뒤에도 판단 범위가 넓지만, 매 경매의 외부 왕복과 저장소 장애 의존성을 감수해야 한다. |
| 안정 해시 소유자 라우팅 | 같은 요청을 같은 SSP로 보내 로컬 상태를 유효하게 만든다. 정상 재시도는 막을 수 있지만, 소유자 장애 때는 보수적 실패 정책이 필요하다. **선택** |

50ms 경매 경로에서는 외부 왕복 최소화가 더 중요하다. 따라서 전 인스턴스 장애까지 저장소로 흡수하는 대신 매 요청 의존성을 추가하는 안보다, 정상 재시도를 로컬에서 막고 소유자 장애는 짧은 실패로 격리하는 안을 택했다.

| 안정 해시 구현 | 판단 |
|---|---|
| Ring Consistent Hash | 최소 이동 성질은 만족하지만 가상 노드와 ring 관리가 필요하다. |
| **Rendezvous Hash** | `hash(요청 키, 노드 ID)`의 최고 점수 노드를 고른다. 현재처럼 리전별 SSP 수가 작고 제한적이면 요청당 `O(n)` 비용은 작고, 구현·설명이 단순하다. **선택** |

## 결과와 감수

- 정상 재시도는 기존 경매 또는 기존 결과를 사용하므로 두 번째 DSP 경매를 만들지 않는다.
- 소유 인스턴스가 DSP 호출 뒤 중단되면 호출 여부를 알 수 없다. 이때 같은 기회는 5초 동안 재경매하지 않고 실패한다. 중복 경매보다 과금·경매 정합성을 우선한다.
- 계획된 축소에서는 기존 소유자를 5초간 drain한 뒤 종료한다. 새 광고 기회만 건강한 인스턴스로 보낸다.
