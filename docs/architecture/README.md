## 2. 아키텍처 원칙

- SSP와 프로젝트 DSP는 서로 다른 회사이며 저장소와 트랜잭션을 공유하지 않는다.
- 두 회사는 각각 두 리전에 능동 배치하고 각 리전의 실행 컨테이너를 여러 AZ에 복제한다.
- SSP는 세 DSP를 병렬 호출하며 회사별 시간·동시성·연결 자원을 격리한다.
- SSP 경매와 렌더링·통지는 우선 같은 애플리케이션의 진입 실행 자원을 사용한다. 실제 경합이 확인될 때만 실행 자원 격리와 독립 배포를 검토한다.
- 프로젝트 DSP의 입찰은 인스턴스 로컬 캠페인 자료와 로컬 예산 권한만 사용한다.
- 캠페인은 시험 전에 같은 버전으로 적재하고 실행 중 변경하지 않는다.
- 프로젝트 DSP의 입찰과 예산 처리는 같은 애플리케이션 프로세스 안에서 실행 자원을 격리한다.
- 캠페인 예산은 전역 책임액, 리전 책임액과 DSP 로컬 권한으로 겹치지 않게 나눈다.
- 페이싱은 각 리전이 자기 책임액을 기간에 맞춰 DSP 리스로 공급하며 리전 간 실시간 합산을 사용하지 않는다.
- 전역 책임 원장은 홈 리전 PostgreSQL 단일 쓰기 권위와 다른 리전의 비동기 복구 사본으로 구성하며 각 리전 예산 원장과 장애 범위를 공유하지 않는다.
- `lurl`·`burl`은 DSP가 입찰 응답에 넣은 OpenRTB URL로 호출한다. DSP는 내부 사건을 커밋한 뒤 본문 없는 일반 HTTP 성공을 반환하며 양사가 공유하는 메시지 기반 시설은 없다.
- `nurl`은 금액을 바꾸지 않는 경매 결과 사건으로 금액 원본과 구분한다.
- SSP와 DSP는 금액 사건을 소유 리전에서 독립 기록한다. SSP 청구 사건의 리전 간 집계는 구현 범위 밖이며, DSP만 전역 예산 책임을 요청 경로 밖에서 조정한다.
- SSP는 자기 청구 근거를, DSP는 실제 접수한 통지를 독립적으로 기록한다. DSP는 중복 호출을 한 번만 반영하고 미도착 통지는 예약 만료로 종결한다. 실제 청구·송금과 업체 간 대사는 범위 밖이다.

## 3. 데이터 권위

| 데이터 | 권위 | 보존 기준 |
|---|---|---|
| 경매 결과·렌더링 증표 | SSP | 경매 응답에서 인증된 증표로 전달하고 서버 상태는 요청 뒤 폐기 |
| 청구 근거·`burl` 전달 책임 | 발급 리전의 SSP 청구 기록 DB | 리전 내부 내구 추가, 다른 리전은 대신 처리하지 않음 |
| 캠페인 실행 자료 | 프로젝트 DSP | 시험 전 버전·체크섬 확인 뒤 로컬 불변 사본으로 적재 |
| 총예산·전역 예비액·리전 책임 봉투 | 프로젝트 DSP 전역 책임 원장 | 책임 이전과 단일 소유권을 강하게 보존 |
| DSP 권한·잠재 지출 | DSP 입찰 인스턴스와 리전 예산 원장 | 로컬 예약, 장애 시 상위 권한 격리 |
| 접수한 `lurl`·`burl` 사건 | 프로젝트 DSP 지역 금액 사건 기록 | 최초·중복·만료를 내부에서 판정하고 일반 HTTP 응답, 미도착 통지는 만료로 종결 |
| 접수한 `nurl` | 프로젝트 DSP 경매 결과 자료 | 금액을 바꾸지 않으며 추적·분석 필요에 맞춰 보존 |
| 페이싱 상태 | 프로젝트 DSP 리전 예산 원장과 DSP 로컬 권한 | 리전 책임액 안의 리스 발급 상태이며 다른 리전과 실시간 합산하지 않음 |
| 지표·로그 | 각 회사 | 파생 자료이며 금액 원본이 아님 |

## 4. ADR 대조 결과

| ADR | Level 2와 Deployment에 반영한 구조 |
|---|---|
| ADR-001 분산 예산 예약 | DSP 애플리케이션의 로컬 권한과 입찰 경로 밖의 원장 관계 |
| ADR-002 다중 리전 원장 | 전역 책임 원장, 리전별 독립 원장과 비동기 복구 사본 |
| ADR-003 리전 예산 이전 | DSP 애플리케이션의 배경 처리가 전역·리전 원장에 접근하고 입찰은 이전을 기다리지 않음 |
| ADR-004 경매 실행 경로 | SSP 애플리케이션, DSP 게이트웨이·DSP 애플리케이션과 경로별 수용량 제한 |
| ADR-005 금액 사건 수렴 | 표준 통지 URL, DSP 내부 멱등 기록과 리스 단위 정산 |
| ADR-006 다중 리전 배치 | 두 회사의 독립 전역 진입, 두 능동 리전, 리전별 다중 AZ 인스턴스 |
| ADR-007 지역 금액 사건 장부 | 회사·리전별 독립 PostgreSQL과 RDS Multi-AZ 배치 |
| ADR-008 전역 책임 원장 | 홈 리전 RDS PostgreSQL 단일 쓰기 권위, 비동기 복구 사본과 자동 승격 금지 |
| ADR-009 SSP 경매 멱등성 | 경매 키의 안정된 소유자 라우팅과 인스턴스 로컬 중복 방지 |

현재 컨테이너안은 다음 기준으로 구성했다.

- 저지연 경매와 재시도 가능한 통지는 우선 실행 자원을 공유하고, 경합 측정 뒤에만 격리 또는 독립 배포를 선택한다.
- DSP 입찰과 예산 제어는 책임과 실행 자원만 구분하고 독립 배포 단위로 만들지 않는다.
- 전역 책임 원장과 각 리전 예산 원장은 물리 저장소 배포를 분리한다. 전역 원장 장애 시 새 책임 이전만 중단하며 지역 활성화 증거를 대조하기 전에는 복구 사본을 쓰기 권위로 승격하지 않는다.
- 확정 지출은 지역 사건을 리스별로 집계해 지역 예산 원장에 한 번 정산하며 전역 책임 원장의 실시간 입력으로 사용하지 않는다.
- 내부 계산 단계와 저장소 스키마는 독립 배포 근거가 없으므로 컨테이너로 만들지 않는다.

## 5. 기술 선택 경계

지역 금액 사건 장부와 전역 책임 원장은 PostgreSQL 계열로 확정했지만 서로 다른 배포 경계다. SSP의 현재 기준과 선택 순서는 [SSP 기술 기준선](technology/ssp.md)을 따른다. DSP 기술은 DSP 컴포넌트 경계를 검토할 때 별도로 정한다.

- 리전 내부 고가용과 높은 동시 권한 발급
- 낮은 할당·GC 부담의 로컬 예약과 캠페인 조회
- 독립 지역 기록, 멱등 HTTP 재처리와 적체 제한
- 절대 기한 전파, 연결 재사용과 회사별 자원 격리

기술 후보는 데이터의 원본성과 복구 계약을 만족해야 한다. 물리 저장소 경계를 바꾸는 선택은 데이터 관점과 관련 ADR을 함께 다시 검토한다.
